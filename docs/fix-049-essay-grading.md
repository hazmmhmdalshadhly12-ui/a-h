# دليل تطبيق إصلاح 049 — تصحيح المقالي بدرجة من نقاط الامتحان

> الطلب: المستر يصحح إجابات الطالب في الامتحان المقالي بدرجة نهائية من
> نقاط الامتحان نفسها (امتحان من 20 → يقدر يدي 20 من 20 أو 17 من 20)،
> ويقدر يعدل الدرجة في أي وقت، ولوحة التفوق تستنى المدرس — الموضوعي
> والمقالي يتpublishوا مع بعض.

## 1) ما الذي تغيّر

### قاعدة البيانات — `supabase/migrations/049_essay_grading.sql`
- **`grade_exam_submission`** (RPC جديد للأدمن): المستر يكتب الدرجة
  النهائية للتسليم من إجمالي درجات الامتحان (مثلاً من 20):
  - الخادم يتحقق: الدرجة بين 0 ودرجة الامتحان الكاملة (لا تجاوز،
    والكسور العشرية مثل 15.5 مسموحة).
  - `manual_score` = الدرجة − الموضوعي الآلي (للشفافية)، و`score` تتحدث
    فورًا — **أي تعديل بعد النشر يظهر للطالب ولوحة التفوق مباشرة بدون
    إعادة نشر**، مع إشعار للطالب «تم تعديل درجتك».
- **بوابة النشر** (`publish_grade` / `publish_exam_grades` — نفس التوقيع
  القديم، لا خطأ 42P13):
  - امتحان فيه أسئلة مقالية: تسليم الطالب **لا يُنشر قبل تصحيح درجته
    النهائية** — الموضوعي والمقالي يتنشروا مع بعض (لوحة التفوق تستنى
    المستر).
  - «نشر الدرجات دفعة واحدة» بينشر **المصحح فقط**؛ غير المصحح يظهر
    «بانتظار تصحيح المقالي» بلا نشر ولا إشعار لحد ما تصححه.
- عمود جديد `essay_graded_at` (علامة «صحح المستر الدرجة») — لا حذف بيانات
  ولا تغيير لأي عمود قائم، والملف قابل لإعادة التشغيل.

### الواجهة — صفحة نتائج الامتحان (الأدمن)
- عمود «الدرجة النهائية»: خانة واحدة «من 20» بدل خانة المقالي المنفصلة —
  راجع إجابات الطالب من «مراجعة» ثم اكتب النهائي (مثلاً 17).
- حالة كل تسليم: «منشور للطالب» / «جاهز للنشر» / «بانتظار تصحيح المقالي».
- الخانة **تظل قابلة للتعديل بعد النشر** — أي تصحيح لاحق يظهر فورًا.
- إشعارات النشر صارت مرة واحدة فقط عند أول نشر (بدل تكرارها).

## 2) خطوات التطبيق على الإنتاج

1. **قاعدة البيانات (خطوة يدوية واحدة):**
   Supabase → SQL Editor → الصق كامل محتوى
   `supabase/migrations/049_essay_grading.sql` → **Run**.
   - يتطلب تنفيذ 047 (part1/part2) و048 قبلها — موجودة كلها في مجلد
     `supabase/migrations`.
   - لا يُمس أي بيانات؛ يمكن تشغيله أكثر من مرة بأمان.
2. **الواجهة:** تُنشر تلقائيًا مع الدفع إلى `main` عبر GitHub Actions
   (Deploy to GitHub Pages).
3. **التحقق بعد التطبيق:**
   - افتح نتائج امتحان فيه مقالي → راجع إجابة طالب → اكتب الدرجة من
     الإجمالي → «نشر».
   - جرب تعديل الدرجة بعد النشر — الطالب يشوف الجديد فورًا ولوحة التفوق
     بتتحدث.
   - «نشر الدرجات دفعة واحدة» على امتحان فيه تسليمات غير مصححة →
     المصحح فقط يتنشر والباقي «بانتظار تصحيح المقالي».

## 3) حالات حدودية محسومة

| الحالة | السلوك |
| --- | --- |
| الدرجة أكبر من درجة الامتحان (21 من 20) | مرفوضة من الخادم |
| درجة سالبة | مرفوضة |
| إعطاء المقالي صفرًا فعليًا (الإجمالي = الموضوعي) | مقبولة وتُنشر (الصفر الحقيقي ليس «بانتظار») |
| تسليمات قديمة منشورة | لا تتأثر — تعديلها متاح في أي وقت |
| امتحان موضوعي بحت | يُنشر فورًا بدون أي درجة يدوية كما كان |
| الطالب يشوف الدرجة | بعد النشر فقط — وقبلها «بانتظار المدرس» |

## 4) الاختبارات الموثقة

- قاعدة PostgreSQL 16 حقيقية: **92/92** — القسم I (20 فحصًا) يغطي:
  التصحيح من الإجمالي، حدود الدرجة، بوابة النشر، النشر الجماعي للمصحح
  فقط، التعديل بعد النشر (يظهر فورًا)، لوحة التفوق (تستنى المستر ثم
  تتحدث)، النتائج القديمة، والمسار القديم.
- محاكاة سياسة الامتحانات: **45/45**. بناء الواجهة: ناجح.
